# NGMC CheckIn / Workforce Operations Platform

## Evidence-safe project profile

This profile is based on accessible local source code. It intentionally omits private identities, URLs, credentials, datasets and internal operating details. Ownership scope and permission for public disclosure must be confirmed before using it as a formal employment achievement.

## Product

A full-stack operations workspace that brings attendance, check-in/check-out, timers, timesheets, projects, assignments, approvals and productivity reporting into one role-aware system.

## Users and problem

The implementation supports administrators, managers and employees/faculty. It addresses fragmented time, attendance, project and approval workflows. The repository does not contain evidence sufficient to publish adoption or business-impact metrics.

## Verified capabilities

- Secure authentication, sessions and role-based authorization
- Attendance, check-in/check-out and persistent timers
- Manual timesheets, projects, tasks, tags and billability
- Assignment, collaboration, approval and controlled reopening workflows
- Team, project, attendance, capacity and productivity views
- CSV/report export and operational dashboards
- Notification delivery with durable fallback
- Audit history, health checks, migrations and backup/retention tooling
- AI-efficiency and costing analysis views
- Automated build, workflow and security tests

## Architecture

The local implementation uses TypeScript, React/Next-compatible components, server routes, Cloudflare/vinext tooling, D1 persistence through Drizzle, role-aware APIs and automated Node tests. This is one operational product ecosystem: attendance and faculty productivity are modules, not separate flagship products.

## Product decisions

The code reflects decisions around role boundaries, private project membership, timer recovery, idempotency, approval locking, auditability, notification fallback and operational reporting. These are stronger portfolio signals than unsupported productivity claims.

## Evidence and limitations

Implementation evidence is REAL. Deployment history and documentation exist locally, but this public profile does not assert current production usage, user count, time savings or commercial outcome. Those require authorized proof.

## Portfolio role

**Secondary case study.** Best used to demonstrate workflow architecture, enterprise controls, technical PM depth and operational product thinking after confidentiality approval.
